# CONSTITUTION.md — закон студии «Юридическая студия»

Статьи вертикали `legal_docs` — дословно из §9.2 ТЗ. У каждой статьи указан метод «Проверка»
(графа ТЗ). Детерминированный офлайн-набор `scripts/validate.mjs` (коды `V-xx`) исполняет
подмножество статей; LLM-judge, RAG и human-review исполняются на платформенном тире (§14 ТЗ).

## Статьи К-01…К-15

- **К-01. Тип документа и стороны с полными реквизитами.** Определены тип документа и стороны
  с полными реквизитами (наименование, ИНН, ОГРН, адрес). *Проверка:* schema-валидатор (V-01).
- **К-02. Все существенные условия предмета по ГК РФ.** В документе присутствуют все существенные
  условия предмета (для договора — по ГК РФ, ст. 432). *Проверка:* constitution_validator (V-02).
- **К-03. Ссылки на нормы ГК РФ корректны и актуальны.** Ссылки на нормы ГК РФ корректны и
  актуальны. *Проверка:* LLM-judge + RAG по consultant.ru/garant.ru (V-03).
- **К-04. Нет внутренних противоречий.** Нет внутренних противоречий: пункты не отменяют друг
  друга. *Проверка:* детерминированный линтер нумерации (cross-reference, V-04).
- **К-05. Реквизиты ИНН/ОГРН/КПП/БИК/р/с валидны по контрольным суммам.** Реквизиты сторон
  валидны по контрольным суммам (ИНН/ОГРН — модуль 11; БИК/р/с — структурно). *Проверка:*
  скрипт `tools/check-requisites.mjs` (V-05, B-08).
- **К-06. Ясность формулировок.** Ясность формулировок: нет двусмысленностей, предложения ≤ 40
  слов. *Проверка:* readability-линтер (V-06, Q-01).
- **К-07. Обработка ПДн по 152-ФЗ.** Обработка персональных данных соответствует 152-ФЗ: цели,
  срок, согласие. *Проверка:* чек-лист ПДн (V-07, B-05).
- **К-08. Ответственность сторон и порядок споров.** Определены ответственность сторон и порядок
  разрешения споров (претензия, суд). *Проверка:* валидатор условий (V-08).
- **К-09. Порядок изменения и расторжения.** Определён порядок изменения и расторжения. *Проверка:*
  валидатор условий (V-09).
- **К-10. Версионирование: дата, место, номер редакции.** Документ версионирован: дата, место,
  номер редакции. *Проверка:* метаданные (V-10).
- **К-11. Нет неюридических оборотов и «воды».** Нет неюридических оборотов и «воды». *Проверка:*
  lint-copy legal-профиль (V-11, B-01).
- **К-12. Сноски на НПА с редакцией/датой.** Сноски на НПА с указанием редакции/даты. *Проверка:*
  валидатор сносок (V-12, Q-05).
- **К-13. Дисклеймер «не является юридической консультацией».** Присутствует дисклеймер «не
  является юридической консультацией». *Проверка:* grep-валидатор (V-13, Q-03).
- **К-14. Формальные атрибуты.** Формальные атрибуты: нумерация пунктов, приложения, места
  подписей. *Проверка:* schema (V-14, Q-04).
- **К-15. Критические документы помечены флагом HITL.** Критические документы помечены флагом
  HITL и не публикуются автоматически. *Проверка:* gate human_review (V-15).

## Гейты

- **G1 Бриф/стороны** — бриф принят, стороны и тип документа определены.
- **G2 Структура условий** — структура существенных условий утверждена.
- **G3 Документ** — артефакт собран и прошёл детерминированную приёмку.
- **G4 Юр-ревью (HITL)** — юридическое ревью человеком, REVIEW.md, приёмка.

## Приёмка

1. Проект не сдаётся, пока `node scripts/validate.mjs projects/<имя>` не вернул `exit 0`
   (V-01…V-15).
2. `node scripts/lint-slop.mjs projects/<имя>` печатает `чисто:` (B-01…B-08).
3. `node scripts/lint-quotas.mjs projects/<имя>` печатает `ИТОГ: N/N · exit 0` (Q-01…Q-05).
4. Цикл принуждения: `node core/loop-engine/cli.mjs projects/<имя> --studio-root verticals/legal_docs`.
