# SKILL-INDEX — приёмы студии «Студия данных»

Реестр приёмов вертикали `data_analytics` (§11 ТЗ). Один приём = директория
`skills/<id>/`: `skill.yaml` (метаданные) + `templates/*.j2` (шаблоны ролей) +
`hooks/*.mjs` (ESM-крючки `pre_execute`/`post_execute`).

| Приём | Назначение | Шаги |
|---|---|---|
| `metric-report` | Собирает разбор: запросы, метрики с формулами, выводы и источник данных. | Определить период → Написать SQL-запросы → Посчитать метрики с формулами → Сформулировать выводы → Указать источник |
| `sql-audit` | Проверяет запросы по закону студии: явные колонки, JOIN, план под контролем, параметризация. | Собрать запросы и план → Проверить колонки и JOIN → Оценить план → Проверить параметризацию → Зафиксировать нарушения |
| `dashboard-spec` | Спека дашборда: вопрос владельца, метрики с формулами и фильтрами, макет. | Разобрать вопрос владельца → Выбрать метрики → Описать формулы и фильтры → Собрать спеку |
| `etl-pipeline` | Идемпотентный ETL: вход → валидация → запись по бизнес-ключу (ON CONFLICT/MERGE). | Объявить вход и схему → Написать ETL → Сделать идемпотентным → Проверить повторный запуск |
| `quality-profile` | Профиль качества набора: nulls, duplicates, types, row_count по каждому полю. | Выделить ключевые поля → Посчитать nulls и дубликаты → Собрать profile.json → Прогнать V-11/Q-04/Q-05 |
| `schema-validate` | Схема входа объявляется до данных; вход валидируется против неё до записи. | Зафиксировать схему → Опубликовать schema.json → Проверить валидацию в ETL → Прогнать V-10 |

Загрузчик — `core/loop-engine/skills.mjs`; рендер шаблонов — `core/loop-engine/template.mjs`.
