# COPYWRITING — экспертный текст без следов ИИ

> Источник истины — `TECHNICAL_SPECIFICATION.md` (v3.0). Здесь — как во всех трёх студиях
> пишется экспертный текст и чем он проверяется. Компонент C-COMMON-02 из
> `docs/RESEARCH-COMPONENTS.md` («микрокопи lint» → расширен до полнотекстовой редактуры).

## Задача

Текст студии должен читаться как написанный человеком-экспертом: факты и числа вместо клише,
глагол вместо связки, живой ритм и **ноль следов машинной генерации** (артефактов копипаста из
чат-ботов). Требование «не отличимо от человека» не доказывается — оно **измеряется прокси**:
детерминированный линтер считает балл чистоты и ловит неустранимые артефакты.

## Две части

1. **Навык письма** `expert-copywriter` — есть в каждой студии:
   - `web_studio` — doc-навык `skills/expert-copywriter/SKILL.md` (SK-22);
   - `mini_apps` / `mobile_apps` — исполняемый навык `skills/expert-copywriter/`
     (`skill.yaml` + `templates/{planner,coder,verifier,fixer}.j2` + `hooks/*.mjs`).
   Навык задаёт редакторский метод: править удалением, связку → глагол, абстракцию → число,
   источник приёма — `ref-16` (mini) / `ref-17` (mobile) / REF web.

2. **Детерминированный линтер** — общий движок `core/vertical-kit/copywriting.mjs`:
   - `analyzeText(text, { genre })` — чистая функция: `{ findings, errors, warnings, score, verdict, metrics }`;
   - раннер `runCopyLint(vertical, copyUrl)` в `core/vertical-kit/index.mjs`;
   - обёртки `scripts/lint-copy.mjs` + спецификация `scripts/copy.json` в каждой студии.

Три студии используют **одно** ядро правил; студия настраивает только `scan`, `extensions`, `genre`.

## Каталог правил

Код всегда формата `[A-Z]{1,2}-\d{2}` (контракт ядра, §6 ТЗ).

### Жёсткие артефакты — `A-xx` (error, гейтят приёмку)

Человек не набирает их руками, поэтому это честный гейт:

| Код | Что ловит |
|---|---|
| A-01 | `oaicite` / `:contentReference[oaicite:N]` (ChatGPT) |
| A-02 | `turn…search` / `citeturn…` (маркеры поиска) |
| A-03 | `utm_source=chatgpt.com` и др. служебные рефереры |
| A-04 | карточки Grok (`grok_card://`) |
| A-05 | цитирование Gemini/Vertex (`[cite: N]`, `vertexaisearch…grounding`) |
| A-06 | инлайновые ссылки-артефакты `【N†…】`, `sandbox:/mnt/data/` |
| A-07 | остатки рассуждений модели (`…`) |
| A-08 | загрузка файла Perplexity (`ppl-ai-file-upload`) |
| A-09 | незаполненные плейсхолдеры (`INSERT_SOURCE_URL`, `URL_HERE`, `20XX-XX-XX`) |

### Стиль и ритм — `C-xx` / `N-xx` / `R-xx` (warn, не гейтят)

Печатаются в сводку `[lint-copy] …` (ядро такие строки игнорирует). Это **не запрет языка**:
длинное тире и «не только… но и» — нормальная русская речь, поэтому они не блокируют сдачу.

- `C-01` канцелярит/штампы-связки, `C-02` связка вместо глагола, `C-03` ИИ-лексика усиления,
  `C-04` faux-insight, `C-05` анонсы, `C-06` фальшивая близость, `C-07` псевдо-терапия,
  `C-08` пустое резюме, `C-09` размытая атрибуция, `C-10` дежурный оптимистичный финал,
  `C-11` сервильность чат-бота, `C-12` формула «сталкивается с вызовами»;
- `N-01` негативный параллелизм, `N-02` драматичное стаккато;
- `C-13` длинное тире в прозе, `R-01` слишком длинные предложения (>26 в среднем или >45 максимум),
  `R-02` монотонный ритм — **мягкие** маркеры (см. ниже).

**Мягкие маркеры** (`SOFT_CODES = [C-13, R-01, R-02]`) показываются как замечания, но **не понижают
балл**. Причина у каждого своя: `C-13` по формулировке — «допустимо, но проверь ритм», а
длинное тире нормативно для русской типографики и прямо требуется законами цеха; `R-01`/`R-02`
считаются по смешанному тексту разметки (HTML/Markdown), где границы предложений и ритм
измерить нельзя надёжно — судить о ритме нужно на живой человеческой редактуре. Балл поэтому
отражает только «жёсткие» стилевые маркеры `C-01…C-12`, `N-01`, `N-02`.

Ритм (`R-01`/`R-02`) к тому же **не измеряется по коду**: раннер передаёт `rhythm=false` для
`.js`/`.css`/`.json` (в них прозы нет — только строки и комментарии), поэтому код не даёт ложных
срабатываний. Считается он **построчно**: склейка строк разметки в одно «предложение» давала
ложные `R-01` (например, 55 «слов» в наборе `dt`/`dd`/`option`).

### Жанры

`genre` в `scripts/copy.json` смягчает часть стилевых правил в научной/юридической/новостной прозе:
`marketing`, `expert`, `product`, `business`, `academic`, `legal`, `news`.

- web_studio → `marketing`; mini_apps → `product`; mobile_apps → `product`.

### Балл и вердикт

`score = clamp(100 − 12·errors − 3·hardWarnings, 0, 100)`, где `hardWarnings` — замечания
`C-01…C-12`, `N-01`, `N-02` (мягкие `C-13`, `R-01`, `R-02` в балл не идут);
вердикт: `errors > 0` → «переписать»; иначе `score ≥ 80` → «чисто», `≥ 55` → «правка», иначе «переписать».

## Как это встроено в цикл (К-21)

`lint-copy` зарегистрирован в `VERTICAL_CHECKS` ядра и стоит в `checks` всех трёх студий
(`validate`, `lint-slop`, `lint-copy`; у web ещё `lint-marketing`). Ядро считает проверку
проваленной, если скрипт напечатал **любую** строку-код или вышел с ненулевым кодом. Поэтому
движок печатает код-строками только жёсткие ошибки `A-xx`, а стиль — сводкой с префиксом
`[lint-copy]`, которую парсер игнорирует. Так гейт ловит машину, а не стиль.

```bash
cd verticals/mini_apps && node scripts/lint-copy.mjs projects/evakuator-vk
# [lint-copy] чисто: файлов 5, ошибок 0, замечаний стиля 9 (C-13, R-02), балл 100
```

## Ограничение (честно)

«Не отличимо от человека» линтером не доказывается. Измеримый критерий здесь — **ноль жёстких
артефактов**, балл стиля и слепая человеческая проверка. Линтер снижает типичные коррекции, но
вкус и смысл остаются за человеком (К-09).

## Как расширять

1. Правило — в `core/vertical-kit/copywriting.mjs` (`ARTIFACT_RULES` / `STYLE_RULES`) с кодом
   формата `X-00` и пометкой жанров `skipGenres`.
2. Студийное — в `scripts/copy.json` студии (`scan`, `extensions`, `genre`, при желании `maxWarnings`).
3. Тест — в `tests/copywriting/copywriting.test.mjs`.
