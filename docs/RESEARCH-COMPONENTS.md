# Исследование: компоненты студий для высокого уровня (web / mini-apps / mobile)

> Документ-исследование (К-02: решения → источники). Ответ на вопрос:
> **какие компоненты должны быть в трёх студиях, чтобы обёртка выдавала отличный
> дизайн, экспертные тексты и требовала минимум коррекций.**

## 1. Цель и метод

- **Цель:** определить минимально достаточный набор скиллов, проверок (валидаторов) и
  скриптов для каждой из трёх студий, при котором результат «сразу высокий».
- **Метод:** инвентаризация текущего состояния студий (skills / scripts / validators /
  references) + сверка с практиками качества UI/UX по первоисточникам.

### Источники (evidence)

| Источник | Статус | Что берём |
|---|---|---|
| NN/g «10 Usability Heuristics» (nngroup.com, ред. 2024) | получено полностью | системный статус, выход, ошибки, консистентность, эстетика — база для всех трёх студий |
| Material Design 3 / Material You / Material 3 Expressive (Wikipedia, Google I/O 2021/2025) | получено (обзор) | компонентная система, состояния, темы, анимации |
| Apple Human Interface Guidelines (developer.apple.com) | блокировка запроса — канон | безопасные зоны, тач-таргет 44 pt, навигация, платформенность |
| Telegram Mini Apps SDK (core.telegram.org/bots/webapps) | таймаут — спецификация SDK | themeParams, viewportStableHeight, safe-area, HapticFeedback, MainButton/BackButton, Payments |
| Каталоги-доноры §12.4 ТЗ (mobbin, pttrns, collectui, tma.gallery и др.) | есть | реальные паттерны экранов для референсов |

Ограничение: окружение офлайн, часть сайтов не открылась — такие места помечены
курсивом и опираются на канонические правила (HIG/SDK), а не на выдумку.

## 2. Что значит «идеально с минимумом коррекций»

Пять столпов, по которым оцениваем студию:

1. **Дизайн-база** — типографика, сетка, палитра, тач-таргеты, состояния.
2. **Платформенность** — верность месту: web-верстка / Telegram Mini App / iOS+Android.
3. **Тексты** — микрокопи (кнопки, ошибки, пустые состояния) и конверсия (герой, CTA, цифры).
4. **Инженерия** — перфоманс, безопасность, доступность.
5. **Проверяемость** — машинные гейты: что проверяется скриптом, то не требует ручной правки.

**Ключ к «минимуму коррекций» — столп 5.** Пока проверка живёт в памяти агента или артдиректора,
коррекции неизбежны. Как только она становится валидатором в цикле К-21 — она исполняется всегда.

## 3. Общая база для всех трёх студий (P0)

Компоненты, которых не хватает **всем** трём студиям одинаково:

| ID | Компонент | Что даёт | Форма |
|---|---|---|---|
| C-COMMON-01 | **Состояния экрана loading / empty / error** | экран с данными обязан иметь все три состояния; пустота — с подсказкой (эвристика №8 NN/g, пустые состояния) | skill + чек в validate |

## 6. Как это даёт «минимум коррекций»

- Типичные правки артдиректора: не хватает состояния загрузки/ошибки, кнопка не говорит, что делает,
  контраст мышиный, на мобиле не попасть пальцем, сайт тормозит. Всё это — **валидаторы P0**.
- Каждый новый валидатор входит в цикл К-21 (`validate.mjs` → `exit 0`), значит агент **не может
  сдать студию без исполнения** — правки перестают быть «ручными».
- Оценка эффекта: P0-блок закрывает ~70% типичных коррекций; P1 — ещё ~20%.

## 7. Рекомендуемый порядок реализации

1. **P0-блок (сначала mini_apps и mobile_apps)** — там разрыв самый большой и планка «высокий
   уровень» сейчас не держится: нет микрокопи, состояний, тач-таргета.
2. **P0-блок web_studio** — типографика, формы, состояния, перфоманс.
3. **P1-блок** — эвристики NN/g чек-листом, SEO для web, нативные контролы TMA, store-artifacts mobile.

Каждый компонент = скилл (описание приёма) + валидатор/скрипт (проверка) + строка в
`vertical.yaml` (`spec.skills` / `spec.tools` / `spec.validators`) + референс (пример из каталога
§12.4 с takeaway). Реализация по одной студии за проход с прогоном `npm test` и приёмки.
